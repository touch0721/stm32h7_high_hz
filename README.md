# stm32h7_high_hz

STM32H743 侧固件：以 SPI2 从机身份接收 FPGA 的高精度测量帧，换算成工程量后驱动串口屏显示。

本仓库是 **MCU（STM32）端**，配套的 **FPGA 测量端**在
[touch0721/fpga_high_hz](https://github.com/touch0721/fpga_high_hz)。

> 两个仓库是两个独立工程：本仓库**不含任何 Verilog / RTL / 比特流**，`fpga_high_hz`
> 也不含 STM32 固件。两边唯一的耦合点是下面定义的 **16 字节 SPI 帧格式**——
> 改帧格式必须两个仓库同步改。

---

## 1. 与 fpga_high_hz 仓库的分工

| | [fpga_high_hz](https://github.com/touch0721/fpga_high_hz) | 本仓库 stm32h7_high_hz |
|---|---|---|
| 运行平台 | FPGA | STM32H743IIT6（LQFP176） |
| 语言 | Verilog / RTL | C（STM32 HAL） |
| 职责 | 等精度测频、TDC 时间间隔测量、方波占空比测量 | SPI 从机收帧、定点换算、文本格式化、串口屏显示 |
| 角色 | SPI **主机**，单向发送 16 字节帧 | SPI **从机**，只接收 |
| 对外接口 | SPI → 16 B 测量帧 | SPI 收帧；USART1 → 串口屏 |
| 是否做测量 | 是，全部测量在这里 | 否，只解析和显示 |

换句话说：**精度由 FPGA 决定，本仓库负责把数字算对、把字排对、把屏刷稳。**

```
        被测信号
           │
           ▼
   ┌───────────────┐   16 B 帧 / SPI 模式 3   ┌────────────────────┐
   │     FPGA      │ ───────────────────────► │  STM32H743 (本仓库) │
   │ fpga_high_hz  │      FPGA 为主、MCU 为从   │      SPI2 从机      │
   └───────────────┘                          └─────────┬──────────┘
                                                        │ USART1 921600
                                                        ▼
                                              ┌────────────────────┐
                                              │ 串口屏 t0 / t1 / t2 │
                                              └────────────────────┘
```

## 2. 功能

只做一件事：把 FPGA 发来的三种测量帧，变成人可读的数值。

| 模式 | 帧头 | 测量内容 | `t0` 显示 | `t1` 显示 | `t2` 显示 |
|---|---|---|---|---|---|
| `001` | `AA AA` | 频率与周期 | 频率与周期测量 | `F=1.00001MHz` | `T=1.00000us` |
| `010` | `AA BB` | 时间间隔 | 时间间隔测量 | `Ts=11.6900us` | 清空 |
| `100` | `AA CC` | 脉冲占空比 | 脉冲占空比测量 | `D=49.99%` | 清空 |

- 频率 / 周期：小数点后 **5 位**，单位自动在 `Hz / kHz / MHz`、`us / ms / s` 之间切换
- 时间间隔：小数点后 **4 位**，单位自动 `us / ms / s`
- 占空比：**0.01%** 分辨率，固定两位小数
- 上电后长时间收不到帧，`t0` 显示 `spi wait`
- 模式切换立即刷新；同一模式最快 **5 Hz**（200 ms）刷新，避免把屏刷死
- 全部换算用 **uint64 整数定点**，不依赖 `printf`、浮点和 `libm`

## 4. 帧格式（16 字节，大端，MSB first）

三种帧统一 16 字节，第 0 字节固定 `0xAA`，最后两字节固定 `00 F0`。

### 4.1 模式 `001`：频率与周期（`AA AA`）

| 字节 | 内容 | 说明 |
|---|---|---|
| `b0 b1` | `AA AA` | 帧头 + 模式 |
| `b2 b3` | `00 00` | 保留 |
| `b4` | `{5'b0, nx[26:24]}` | 高频计数高 3 位 |
| `b5..b7` | `nx[23:0]` | 1 s 闸门内的上升沿数 |
| `b8` | `{3'b0, n0[28:24]}` | 周期计数高 5 位 |
| `b9..b11` | `n0[23:0]` | 被测周期，单位 300 MHz 拍 |
| `b12 b13` | `00 00` | 保留 |
| `b14 b15` | `00 F0` | 帧尾 |

`nx` 为 27 位，1 s 闸门下的可测上限约 **134.2 MHz**。

### 4.2 模式 `010`：时间间隔（`AA BB`）

| 字节 | 内容 | 说明 |
|---|---|---|
| `b0 b1` | `AA BB` | 帧头 + 模式 |
| `b2 b3` | `00 00` | 保留 |
| `b4..b7` | `t1_data[63:32]` | 粗计数，200 MHz → **5 ns/拍** |
| `b8..b11` | `t1_data[31:0]` | TDC 小数，单位 **ps** |
| `b12 b13` | `00 00` | 保留 |
| `b14 b15` | `00 F0` | 帧尾 |

时间 = `粗计数 × 5000 ps + TDC 小数(ps)`。

### 4.3 模式 `100`：方波占空比（`AA CC`）

| 字节 | 内容 | 说明 |
|---|---|---|
| `b0 b1` | `AA CC` | 帧头 + 模式 |
| `b2 b3` | `d_p` | 周期路的 TDC 码差，**10 位补码**，高 6 位为 0 |
| `b4 b5` | `d_h` | 高电平路的 TDC 码差，**10 位补码**，高 6 位为 0 |
| `b6..b9` | `P_c` | 周期粗计数，28 位有效 |
| `b10..b13` | `H_c` | 高电平粗计数，28 位有效 |
| `b14 b15` | `00 F0` | 帧尾 |

## 5. 分帧策略：字节流 + 软件同步

FPGA 在帧与帧之间**不拉高 CS**，NSS 边界和帧边界对不齐，所以固件**不按 16 字节硬切**：

1. `HAL_SPI_Receive_IT()` 每次固定收 16 字节，双缓冲 ping-pong，收满立刻换块重挂；
2. 收到的字节**按序追加**进 512 字节环形缓冲 `stream[]`（约 32 帧）；
3. 主循环里用 `Stream_GetFrame()` 做软同步，同时满足四个条件才认一帧：
   - `[0] == 0xAA`
   - `[1] ∈ {0xAA, 0xBB, 0xCC}`（同时确定模式）
   - `[14] == 0x00`
   - `[15] == 0xF0`
4. 不满足就**滑 1 字节**重找；缓冲区被写爆时丢最旧的；
5. 一次消费掉所有积压帧，**只显示最后一帧**，避免慢屏拖出延迟；
6. 半帧卡死看门狗：一个 16 字节块只收到一部分、超过 200 ms 没有新字节，
   就 `HAL_SPI_Abort()` 后重新挂接收，防止 HAL 永远停在 `BUSY_RX`。

这套机制能扛住丢帧、杂散字节和半字节位偏移；真正的位偏移（丢 SCK 脉冲导致整帧右移）
无法靠软件还原，只能丢这一帧等下一帧。

## 6. 换算与标定

### 6.1 频率：以 1 MHz 为界，两条路径

判据用 `n0` 而不是 `nx`，因为 `n0` 不受毛刺影响：
`n0 > 300` ⇔ `f < 1 MHz`。

| 区间 | 频率 | 周期 | 理由 |
|---|---|---|---|
| `f < 1 MHz`（`n0 > 300`） | `f = REF_CLK_CAL_HZ / n0` | `T = n0 / REF_CLK_CAL_HZ` | `nx` 太小，几十个毛刺计数就是百分之几的误差；`n0` 有 30 万以上，±1 拍仅 3e-6 |
| `f ≥ 1 MHz`（`n0 ≤ 300`） | `f = nx × (1e7 − N) / 1e7` | `T = 1 / f` | `n0` 只剩 300 以内、仅 3 位有效数字；`nx ≥ 1e6` 的相对误差只有 1e-6 |

低频时频率和周期**都从 `n0` 推**，所以恒有 `f × T = 1`，不会互相矛盾。

### 6.2 参考时钟标定

实测 50 / 25 / 12 MHz 三点，读数系统性偏高 3.8 ~ 4.2 ppm，且**与频率成正比**
（不是固定多算几个沿），因此按比例修正：

```c
#define REF_CLK_HZ          300000000ULL   // n0 的拍频
#define FREQ_CAL_PPMX10     38UL           // 修正 3.8 ppm，0 = 关闭
#define REF_CLK_CAL_HZ      (REF_CLK_HZ - (REF_CLK_HZ / 10000000ULL) * FREQ_CAL_PPMX10)
// = 299,998,860 Hz
```

两条路径共用同一个系数，过 1 MHz 分界不会跳变。现场标定数据与推理过程记在
[`spi.h`](Core/Inc/spi.h) 的注释里。

### 6.3 时间间隔

```c
t_ps = coarse * 5000 + ps;   // 5 ns 粗拍 + ps 级 TDC 小数
```

### 6.4 占空比

TDC 单级延迟 `tau = 19.5 ps`，不是整数，所以全部换算到 **0.1 ps** 再算：

```
H = H_c × 5000 + d_h × 19.5 − 2600   (ps)
P = P_c × 5000 + d_p × 19.5          (ps)
duty = H / P
```

- `P1_TDC_TAPS = 384`：物理延迟线级数，决定码位宽（0~383）
- `P1_TDC_NTAP_PIT = 256`：一个 5 ns 粗拍覆盖的有效格数 = 5000 / 19.5，决定 `d` 的合理范围约 ±256
- `2600 ps` 是两条 TDC 链之间的**固定**时间差，**只扣在 H 上**，P 不扣
- `d` 若落在 256~383，说明零头已绕过一个整拍，应减 256 再使用（FPGA 侧约定）

> 固定 offset 的必然表现：理想的 50.00% 方波，1 MHz 时显示约 **49.74%**，
> 100 kHz 时约 49.97%，10 kHz 及以下接近 50.00%。偏差 = 2600 ps / 周期，属预期而非 bug。

## 7. 串口屏协议

屏幕只当"哑终端"，每帧刷新发 1~3 条指令，控件固定为三个文本控件：

| 控件 | 内容 |
|---|---|
| `t0` | 当前测量模式 |
| `t1` | 主测量值（频率 / 时间间隔 / 占空比） |
| `t2` | 周期（仅频率模式；切到其它模式时发空串清掉） |

指令格式：

```
t1.txt="F=1.00001MHz"<FF><FF><FF>
```

- 每条指令以 **3 个 `0xFF`** 结束
- 一次刷新先拼进 `sc_buf`，再按 `FF FF FF` 切开，**一条一次 `HAL_UART_Transmit`**
- 指令之间插 **2 ms** 间隙（`SC_CMD_GAP_MS`），给屏解析和重绘留时间；
  连续灌多条会让屏来不及消费，表现为不刷新或只刷一部分
- 指令**内部**必须连续，不能有间隙，否则屏会按字节间隔超时丢掉半条
- 同一模式刷新间隔 **200 ms**（`SPI_DATA_TX_MIN_GAP_MS`），模式切换立即刷新

### 中文字库

模式名默认按 **GBK** 字节转义写死在 `spi.h` 里（源码是 UTF-8，直接写中文会以 UTF-8 发出，
而大彩 / 淘晶驰类屏默认字库是 GB2312，会乱码）。`SC_CN_USE_GBK` 三档：

| 值 | 行为 |
|---|---|
| `1` | GBK 中文（默认，屏字库选 GB2312） |
| `0` | UTF-8 中文（字库按 UTF-8 生成时才用） |
| `2` | 英文 `FREQ / TIME / DUTY`（排查中文字库问题的对照档） |

屏幕端需要在 HMI 工程里建好 `t0 / t1 / t2` 三个文本控件，并把字体设为 GB2312。
若数字能显示而 `t0` 空白，基本就是字库没配对。

## 9. 构建与烧录

**环境**

- Keil MDK-ARM 5.32（ARM Compiler 5 / AC5）
- STM32CubeMX 6.18.1
- STM32Cube FW_H7 **V1.13.0**

**步骤**

1. 打开 [`MDK-ARM/stm32h7_high_hz.uvprojx`](MDK-ARM/stm32h7_high_hz.uvprojx)
2. Target 选 `stm32h7_high_hz`，器件 `STM32H743IITx`
3. `Rebuild` → `Download`（ST-Link / J-Link 均可）
4. 串口屏接 `PB14`（TX）与 GND，波特率 921600

**用 CubeMX 修改外设**

打开 [`stm32h7_high_hz.ioc`](stm32h7_high_hz.ioc) 修改后重新生成即可，业务代码都在
`USER CODE` 区内。两点注意：

- `SPI2_IRQHandler()` 写在 `spi.c` 末尾（因为 CubeMX 里没勾 SPI2 的 NVIC）。
  如果以后在 CubeMX 里勾上了，要删掉这个函数，否则重复定义。
- 刷新参数、标定系数都在 `spi.h`，不需要改 `.c`。

**依赖**

格式化路径不调用 `printf`、浮点和 `libm`，是否勾选 MicroLIB 都能编译。
`usart.c` 里的 `printf` 重定向只在定义了 `__MICROLIB` 时参与编译，当前未启用。

## 10. 上电自检

1. 只给 MCU 上电、FPGA 不发数据 → `t0` 显示 `spi wait`
2. FPGA 开始发帧 → `t0` 变成模式名，`t1` 出现数值，频率模式下 `t2` 出现周期
3. 切换模式 → 立即刷新，`t2` 自动清空
4. 拔掉 SPI 线 → 屏保持最后一次数据（`SPI_WAIT_ALWAYS = 0`）；
   想看实时 `spi wait` 提示可把它改成 `1`

## 11. 已知限制

1. **单向**：MCU 只接收，不回传任何数据给 FPGA；没有握手、没有重传。
2. **1 MHz 分界是取舍**：100 kHz ~ 1 MHz 区间走 `n0`，只有 300~3000 个计数
   （量化 3e-4 ~ 3e-3），比高频路径的 1e-6 差 2~3 个数量级。这是为了压住低频毛刺
   有意选的，理论最优分界取决于每闸门毛刺计数。
3. **频率上限**：`nx` 为 27 位，1 s 闸门对应约 **134.2 MHz**。
4. **TDC 温漂**：`tau` 实测在 18.6 ~ 19.5 ps 之间随 PVT 变化，4.8% 的差异在 1 MHz、
   `d=250` 时约等于 0.02% 占空比。要守住 0.01% 就得定期重标或按温度查表。
5. **固定 offset**：2600 ps 只扣在 H 路，短周期下会显示 49.74% 这类偏差（见 6.4）。
6. **屏幕字库**：中文模式名依赖屏端 GB2312 字库；字库不对时 `t0` 空白，数字正常。
7. **协议强耦合**：16 字节帧格式由两个仓库共同约定，改动必须同步，
   且没有版本号字段可用于兼容判断。
